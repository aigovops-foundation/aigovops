The shared clock — every demo, same spine

  1. 0:00Hook — name the persona, name the pain, invite the volunteer.
  2. 0:45🟢 Good path — do the task live, narrating each choice out loud.
  3. 3:45🔴 Bad path — the same task, run the way most people run it. Staged, never shipped.
  4. 5:45The tell — the one question the audience can ask forever after.
  5. 6:15Receipts — save prompt, output, and human edit to the hint-log. Send-off in English and Spanish.

Staging rules — the bad path is theater, not malpractice

  • Stage, don’t ship. Show the drafted reply, the deleted approval node, the toggle — never actually publish, post, send, or record the bad thing.
  • Fake data only. Synthetic patients and customers. No real student, patient, customer, or elder data on screen, ever.
  • Consent is part of the show. Any demo that records audio asks the room out loud first.
  • Pre-run every bad path the night before; keep the screenshot as a fallback slide.
  • Blame configurations, not brands. “A chatbot without sources,” not a product name.

The Block-3 close

Twenty-five demos, three moves

By the end, the room has watched the same three moves win twenty-five times — and discovered the three-Yes framework empirically before anyone said the word “framework.”

1 · Citation or it didn’t happen

Every good path clicked through to a source; every bad path was confident and unclickable. Yes-1: does it work?

2 · The human stays on the trigger

Every good path had a person edit, approve, or sign; every bad path deleted that node. Yes-2: is it safe?

3 · Translation is a safety feature

Every good path reached the Spanish-first neighbor, the field crew, the elder; every bad path pretended English was the whole town. Yes-3: does it reach everyone?
